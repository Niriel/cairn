### [ ] 1.2 JWT auth middleware and UUID validation

**Created:** 2026-05-24T18:59:33Z
**Completed:**

**Why:** Every protected route (R3, R4) needs bearer-token verification and
UUID extraction before file-path construction. Landing the middleware in its
own task keeps 1.3 (the complex upload route) focused on image processing.

**Prerequisites:** Task 1.1 (Express app scaffold exists).

**Decisions:**
- Middleware function: `requireAuth` in `src/middleware/auth.ts`. It reads
  `Authorization: Bearer <token>`, calls `jose.jwtVerify(token, secret,
  { algorithms: ['HS256'] })`, checks the UUID regex
  `/^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$/i` on the
  `sub` claim, then sets `req.uid = sub` and calls `next()`.
- On any failure (missing header, bad signature, expired token, UUID mismatch)
  it returns HTTP 401 with `{ error: "Unauthorized" }`. UUID mismatch returns
  HTTP 400 with `{ error: "Invalid uid" }`.
- The JWT secret is read from `process.env.GOTRUE_JWT_SECRET`. If the env var
  is absent the middleware throws at startup (fail-fast, not at request time).
- TypeScript: extend `express.Request` with `uid: string` via a declaration
  merge in `src/types/express.d.ts` so route handlers can use `req.uid`
  without casting.
- Tests sign real tokens with `jose.SignJWT` using a test secret so they don't
  mock the crypto path — they test the actual behaviour.

**Files:**
- `sidecar/src/middleware/auth.ts` (create)
- `sidecar/src/types/express.d.ts` (create) — `declare global { namespace Express { interface Request { uid: string } } }`
- `sidecar/test/auth.test.ts` (create)

**Steps:**
1. Create `sidecar/src/types/express.d.ts` with the Request extension for
   `uid`.
2. Create `sidecar/src/middleware/auth.ts` per Decisions. Guard the secret at
   module load:
   ```ts
   if (!process.env.GOTRUE_JWT_SECRET) throw new Error('GOTRUE_JWT_SECRET is required');
   const secret = new TextEncoder().encode(process.env.GOTRUE_JWT_SECRET);
   ```
   Using `process.env.X!` alone does NOT throw — it silently encodes `"undefined"`.
   The guard above achieves the fail-fast behaviour described in Decisions.
3. RED — Write `sidecar/test/auth.test.ts` with a minimal Express app that

   - Valid token with correct UUID-format `sub` → 200.

### [ ] 1.3 POST /avatars — security-gate tests and full route implementation

**Created:** 2026-05-24T18:59:33Z
**Completed:**

**Why:** The upload route is the security-critical path (R5, R7). Three
automated tests for the load-bearing gates must be written and confirmed red
before the implementation is written, per the TDD convention.

**Prerequisites:** Task 1.2 (auth middleware attaches `req.uid`). The
`POSTGREST_URL` env var must be documented (set in test as a mock URL).

**Decisions:**
- Multer configured with `limits: { fileSize: 8 * 1024 * 1024 }` and storage
  `multer.memoryStorage()` so the file bytes land in `req.file.buffer`.
  Multer emits error code `LIMIT_FILE_SIZE` when the limit is exceeded; the
  Express error handler turns this into HTTP 413.
- Magic-byte check: call `fileTypeFromBuffer(req.file.buffer)` (from the
  `file-type` package). If the returned `mime` is not in
  `['image/jpeg', 'image/png', 'image/webp', 'image/heic']`, return 415.
  This check is in `src/lib/validate.ts` as a pure function.
- Decoded-bounds check: `const meta = await sharp(buffer).metadata()`. If
  `meta.width > 4096 || meta.height > 4096`, return 422. Also in
  `src/lib/validate.ts`.
- Resize: `await sharp(buffer).resize(256, 256, { fit: 'cover' }).webp({ quality: 80 }).toBuffer()`.
- Atomic write: write to `path.join(avatarsDir, \`${uid}.webp.tmp\`)`, then
  `await fs.rename(tmp, dest)`. The avatarsDir is sourced from
  `process.env.AVATARS_DIR` (default `/srv/cairn/avatars`).
- PostgREST call: `fetch(\`${process.env.POSTGREST_URL}/rpc/bump_avatar_version\`,
  { method: 'POST', headers: { Authorization: \`Bearer ${token}\`,
  'Content-Type': 'application/json' }, body: '{}' })`. The bearer token
  passed to PostgREST is the same token the user sent to the sidecar.
- PostgREST failure: if the `bump_avatar_version` fetch fails (network error
  or non-2xx response from PostgREST), return HTTP 502 with
  `{ error: "version bump failed" }`. The file is left on disk — the orphan
  sweeper reconciles it. Add this case to the Express error handler.
- Return: `{ version: <n>, url: \`/avatars/${uid}.webp?v=${n}\` }`.
- Tests mock `fs.rename` and the PostgREST fetch to avoid real filesystem and
  network calls. For the image-bomb test, use `vi.mock('sharp', ...)` at the
  top of the test file to replace the entire `sharp` module with a factory.
  **ESM default-export shape is required:** `sharp` is imported as a default
  export (`import sharp from 'sharp'`), so the factory must use a `default` key:
  ```ts
  vi.mock('sharp', () => ({
    default: vi.fn().mockReturnValue({
      metadata: vi.fn().mockResolvedValue({ width: 5000, height: 5000 }),
      resize: vi.fn().mockReturnThis(),
      webp: vi.fn().mockReturnThis(),
      toBuffer: vi.fn().mockResolvedValue(Buffer.alloc(100)),
    }),
  }));
  ```
  Without the `default:` wrapper, `import sharp from 'sharp'` resolves to
  `undefined` and `sharp(buffer)` throws `TypeError: sharp is not a function`.
  **Do not use `vi.spyOn(sharp.prototype, ...)` — sharp uses native libvips bindings
  and prototype-level spying does not reliably intercept native call paths.**
  Sharp is never invoked in the wrong-magic-bytes or body-size tests — those paths
  reject before reaching `checkDecodedBounds`. No per-test mock reset is needed;
  only the image-bomb test requires the sharp mock to be active. For the
  wrong-magic-bytes test, construct a buffer that starts with `0x00 0x00 0x00 0x00`
  (no valid image format has a null-byte magic). For the body-size test, create a
  `Buffer.alloc(9 * 1024 * 1024)` payload.
- **`upload.test.ts` must also mock `sharp`** — the route handler calls
  `checkDecodedBounds` (which calls `sharp(buffer).metadata()`) and then
  `sharp(buffer).resize(...).webp(...).toBuffer()` directly. Without a sharp
  mock in `upload.test.ts`, both calls throw on a fake JPEG buffer and the
  handler returns 500 instead of 200. Add the same `vi.mock('sharp', ...)`
  factory (with `default:`) to `upload.test.ts`, but with `metadata()` returning
  `{ width: 100, height: 100 }` (valid dimensions) so the bounds check passes.

**Files:**

### [ ] 2.2 Caddy config and docker-compose service

**Created:** 2026-05-24T18:59:33Z
**Completed:**

**Why:** Caddy is the serve path for avatar bytes. Creating the Caddyfile and
wiring the `caddy` service into compose gives local dev the same read path as
production and lets the 0503 Playwright tests hit real avatar URLs. (R9)

**Prerequisites:** Task 2.1 (named `avatars` volume exists in compose).

**Decisions:**
- `caddy/Caddyfile` listens on `:80` (no TLS in local dev) and uses two
  distinct matchers on the `/avatars` prefix (per `plans/0500_avatars/PLAN.md`):
  (1) a named matcher `@sidecar_writes { method POST DELETE; path /avatars* }`
  with a `reverse_proxy sidecar:3001` directive — routes POST and DELETE to the
  sidecar; (2) a `handle_path /avatars/*` block with `file_server` and a
  `header` directive that sets `Cache-Control "public, max-age=31536000,
  immutable"` — serves static WebP files for GET requests. A single
  `handle_path` block cannot serve both roles: `file_server` returns 405 for
  POST and DELETE.
- The `caddy` docker-compose service uses a fully pinned image tag matching the
  project's convention (see `PostgREST v12.2.3`, `GoTrue v2.158.1` in
  `docker-compose.yml`). Do not use `caddy:latest` or the floating `caddy:2`
  tag. At implementation time, look up the current stable patch on
  hub.docker.com/r/library/caddy and pin to that exact version (e.g.
  `caddy:2.9.1`). Exposes host port 8080 → container port 80
  (avoids requiring root for port 80 on the dev host, and avoids clashing with
  other local services). Mounts `./caddy/Caddyfile:/etc/caddy/Caddyfile:ro` and
  the named `avatars` volume at `/srv/cairn/avatars:ro` (read-only — Caddy never
  writes).
- The `caddy` service has **no `depends_on`** for the sidecar. Docker named
  volumes are created by the compose runtime at `docker compose up` time — not by
  a service process. Caddy serves static files and has no functional dependency on
  the sidecar being alive.
- Port 8080 (host) is the dev avatar endpoint. The 0503 plan will set Vite
  proxy rules: `/avatars` POST/DELETE → `http://localhost:8080` (which Caddy
  then proxies to the sidecar), GET `/avatars/*` → `http://localhost:8080`
  (Caddy file_server). Both write and read paths go through Caddy, matching
  production routing. The 0503 plan owns that wiring; this plan just ensures
  Caddy and the sidecar are running.
- `caddy/` directory must be created as part of this task.

**Files:**
- `caddy/Caddyfile` (create)
- `docker-compose.yml` (modify — add `caddy` service)

**Steps:**
1. Create `caddy/` directory.
2. Write `caddy/Caddyfile`:
   ```
   :80 {
       @sidecar_writes {
           method POST DELETE
           path /avatars*
       }
       reverse_proxy @sidecar_writes sidecar:3001

       handle_path /avatars/* {
           root * /srv/cairn/avatars
           file_server
           header Cache-Control "public, max-age=31536000, immutable"
       }
   }
   ```
3. Add the `caddy` service to `docker-compose.yml` per Decisions. No
   `depends_on` is needed — the named volume exists as soon as compose starts.
4. Run `docker compose config` to validate the updated compose file.
